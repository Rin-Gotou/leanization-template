# 数学論文のLean化を進める

日本語で報告する。AGENTS.md、paper/SUBJECT_RULES.md、
notes/FORMALIZATION_STATUS.md、notes/LEAN_PLAN.md、paper/revision.json、
現行原稿とLean設定を読み、保存済みファイルの現状を確認する。

1. 初回は形式化対象のパス・版・SHA-256を記録する。後の原稿変更では影響を確認する。
2. 定義・仮定・主張・依存関係を読み、実装順と不足を計画に記録する。
   初回は調査と計画を一単位としてよい。
3. 次回以降は小さな定義・補題を一単位選ぶ。導入済みLean・mathlibのソースを
   先に検索し、宣言の完全名・適用条件・出典を記録する。
4. 必要な依存だけを互換性のあるコミットで固定する。見つからないだけで
   ライブラリに存在しないと断定しない。
5. 数学的役割と依存関係でモジュールを分け、公開モジュールをPaperProject.leanに
   追加してlake buildを実行する。sorry・admit・独自axiomとその依存を完了扱いしない。
6. 論文との対応をdocs/linking-conventions.mdに従いproposedで提案する。
   抽象的な前提補題はwork: IDの作業目的リンクを使い、実装範囲と残る接続を明記する。
   既存リンクの対象が進んだら参照宣言も更新する。人間のコメント・レビューは保護する。
7. TeXやリンク変更時はnpm run check:paper、npm run validate:linksも実行する。
   Leanビルド、リンク検査、数学的対応、人間レビューを別々に記録する。
8. 実装済み部分、論文との差異、未接続部分、検証結果、次の候補を進捗と引き継ぎへ記録する。
9. 結果を日本語で報告して一単位を終える。コミット・pushは依頼された場合だけ行う。

原稿や比較基準の版はこの操作では進めない。「Lean相談」だけなら質問を待つ。
